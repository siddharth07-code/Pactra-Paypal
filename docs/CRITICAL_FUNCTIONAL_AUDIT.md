# Critical functional repair — 12 November 2026

Changes are local on `main`. No hosted database writes, deployment, commits, pushes, or historical evidence repair were performed. Existing backups and migrations were preserved.

## Confirmed causes and repairs

- Negotiation acceptance SSE used `agreedPrice`, while the arena displayed `unitPrice`. Acceptance now carries both fields and the mandate currency; the UI also reads the legacy field. Persisted agreements retain the accepted price, quantity, shipping, landed total, terms, supplier, SKU, and mandate revision.
- Supplier simulation and Gemini prompts hardcoded dollar symbols. They now use the commercial currency. Supplier replies and agreements explicitly identify simulation; new agreements record `vendorProvenance=SIMULATED_VENDOR` and `supplierCommitmentVerified=false`. Gemini prose cannot substitute a different amount or currency: the displayed proposal is generated from validated structured values.
- Negotiation previously certified a standalone Merkle tree of raw payloads, while FX checked the canonical persisted Flight Recorder chain. Negotiation now records its actual mandate, catalog snapshot, rounds, and hash-bound agreement in that chain before certification. The returned tree and persisted chain have the same root. Appending FX events preserves verification of the commercial certificate's genuine earlier prefix.
- Commercial verification requires the accepted agreement hash inside the certified prefix. Checkout requires an actual recorded agreement commitment. Missing flight records are no longer synthesized by audit/checkout/capture. Re-audit refuses agreements without recorded term commitments. ACWORLD no longer mutates roots while auditing. Tampered terms and unrelated roots remain blocked.
- Locked FX commitments could previously be replaced with `renew=true`. Replacement is now rejected, including expired locked commitments, pending explicit reconciliation. Duplicate locks retain the original conversion hash. Lock time is recorded separately from provider publication, retrieval, quote creation, and expiry, and committed in the lock event. Database persistence preserves the immutable quote while recording the lock transition.
- Reference-rate conversion now handles configured INR, USD, EUR, and GBP pairs with explicit inverse or direct conventions and integer HALF_UP arithmetic. Same-currency conversion must preserve the amount at rate 1. The existing PayPal settlement route remains INR→USD; native supported PayPal currencies settle directly. Unsupported currencies fail closed. Demo FX remains explicitly labelled and supplies no invented rates for additional pairs.
- Settlement totals now use exact integer minor-unit arithmetic. Settlement displays the saved agreement's quantity, shipping, delivery and returns before legacy display fallbacks. The UI now uses the same PayPal currency support check as the backend, so native EUR and GBP no longer incorrectly require the INR FX bridge.
- Manual sourcing now preserves optional product details, category, and reference unit price in the mandate snapshot and mandate evidence. Reference prices are explicitly buyer inputs, never supplier offers. Changing currency clears the reference price instead of relabelling it. Catalog selection copies the product identity and reference price into a request while preserving quantity and budget. Required specifications, condition, monetary precision, and safe quantity bounds receive server validation. These are single-product procurement mandates, not a multi-product inventory system.
- Channel3 used an undocumented hostname/endpoint and Bearer authentication, expected a nonexistent procurement-quote response, and filled absent currencies from the mandate. It now uses documented `POST https://api.trychannel3.com/v1/search` with `x-api-key`, validates listing prices/currencies/HTTPS links, and preserves catalog listings across session recovery. A configured provider failure is actionable and never substitutes demo offers. The documented catalog response does not provide shipping, delivery or return commitments: listings are displayed for merchant review and cannot become executable procurement quotes with invented terms. Without a key, existing demonstration catalogs remain explicitly labelled.
- A real structured Gemini proposal timed out with default dynamic thinking. Gemini 2.5 Flash/Flash-Lite proposal calls now bound output to 1,024 tokens and disable dynamic thinking for this constrained proposal task. Other models retain their own supported thinking configuration. Structured validation and deterministic guardrails remain mandatory. The repaired live structured INR proposal succeeded with `GEMINI_LIVE` provenance.
